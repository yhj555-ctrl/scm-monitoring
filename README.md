# SCM 리스크 모니터링

구매팀 SCM 관점에서 만든 공급업체·원자재·환율·물류 리스크 모니터링 대시보드입니다.
PR팀의 `pr-monitoring-v2` 구조(메인 대시보드 + 소스별 서브 모니터링 페이지)를 그대로 차용했습니다.

## 페이지 구성

| 경로 | 내용 |
|---|---|
| `/` | 통합 리스크 대시보드 (총 모니터링 건수, 고위험 건수, 업체평가 리스크 TOP5, 최근 이슈) |
| `/suppliers` | **업체평가 리스크 관리** — 99개 공급업체 AI 평가 결과. 행 클릭 시 '24/'25년 재무·평가 상세 팝업. "공시정보" 열에서 DART 최근 공시 확인 |
| `/materials` | **원자재·환율 실시간 모니터링** + 하단에 원자재·환율 관련 최신 뉴스 |
| `/news` | **공급업체 뉴스 실시간 크롤링** — 업체명이 제목에 실제로 포함되는지 재검증, 최근 1년 이내만 표시, 열 클릭 정렬 |
| `/logistics` | 물류/리드타임 모니터링 — 대한민국 기준 중국·대만·미국·유럽·국내 구간 (아직 목업) |
| `/competitors` | **경쟁사 동향** — KT · LG유플러스 · SK텔레콤 장비·서비스 구매/공급업체 관련 뉴스, 통신사별 구분 |

모든 실시간 데이터는 **매일 08:00(KST)** 에 자동 갱신됩니다.

## 정렬 (열 클릭)

**모든 페이지의 모든 표·리스트**가 클릭으로 정렬됩니다.

- 표: 열 제목(`<th>`)을 클릭 — 처음 클릭하면 정렬, 같은 열을 다시 클릭하면 오름↔내림차순 토글,
  현재 정렬 중인 열에는 ▲/▼ 표시가 붙습니다. (대시보드 3개 표, 업체평가 리스트, 원자재/반도체/
  환율 표, 물류 구간별 표가 모두 해당)
- 카드형 리스트(뉴스류: `/materials` 하단, `/competitors`)는 열이 없는 대신 리스트 위에
  "정렬: 게재시각 · 제목 · 출처" 버튼이 있어 클릭하면 같은 방식으로 정렬됩니다.
- 구현: 공용 훅 `components/useSortableTable.tsx` (정렬 상태 관리) + `lib/sort-utils.ts`
  (문자열/숫자/리스크등급 비교 헬퍼). 표마다 셀 렌더링만 다르고 정렬 로직은 공유합니다.

## 상단 네비게이션 — 오늘 날짜·서울 날씨·환율

로그아웃 버튼 왼쪽에 두 줄로 표시됩니다: **① 오늘 날짜 + 서울 날씨(Open-Meteo, 무료·키 불필요)**,
**② USD/KRW 환율 + 기준 시각**. `app/layout.tsx` 에서 서버 컴포넌트로 조회해 `components/Nav.tsx`
에 props 로 내려줍니다. 환율은 `/materials` 와 같은 소스(Frankfurter)를 재사용합니다. 다른 페이지와
동일하게 매일 08:00(KST)에 자동 갱신됩니다. 구현: `lib/live/weather.ts`.

## 차트 시각화

각 페이지 상단에 실제 데이터 기반 그래프를 넣었습니다. 외부 차트 라이브러리 없이 순수 SVG로
직접 그리는 서버 컴포넌트라 클라이언트 JS 비용이 없고, 페이지 색상 테마(`app/globals.css` 의
CSS 변수)와 항상 같은 색을 씁니다. 구현: `components/charts/`, 색상 매핑: `lib/chart-colors.ts`.

| 페이지 | 그래프 |
|---|---|
| `/` | 도넛: 공급업체 리스크 등급 분포 · 막대: 위험/유의 TOP5 종합점수 |
| `/suppliers` | 막대: 최종등급별 업체 수(7등급) · 도넛: 리스크 상/중/하 비율 |
| `/materials` | 막대: 품목별 전일 대비 변동률 · 선형: 전일→현재 변동률 추이 |
| `/news` | 막대 + 도넛: 수집 뉴스의 리스크 등급 분포 |
| `/logistics` | 그룹 막대: 지역별 평균 리드타임(현재 vs 평시) · 도넛: 구간 상태 구성 |

모두 실측/집계값만 사용합니다(가짜 시계열 없음) — `/materials` 의 선형 그래프는 "전일 종가 → 현재가"
2개 실제 지점을 잇습니다.

## 공급업체 평가 데이터

`lib/suppliers.ts`에는 "주요_공급업체_99개_AI평가기준_스코어링" 원본 엑셀의 "종합평가 결과" 시트에서
추출한 실제 데이터가 그대로 들어 있습니다:

- 기본: 업체명, 사업자번호, 유형, 담당 구매원, '25년 계약금액, 최종등급, 참고사항
- `fy24` / `fy25`: '24년·'25년 재무 (자산·유동자산·자본총계·부채·매출액·영업이익·당기순이익·영업/경상/투자활동현금흐름) — **단위: 천원**
- `scoring`: 항목별 값과 배점 (부채비율, 부채변동, 영업이익률, 매출액 성장률, 매출액 규모, 현금흐름, 종합점수)

`#DIV/0!`·`#VALUE!`·`점수오류` 등 계산 불가 셀은 `null` 로 처리했습니다.

`/suppliers` 표에서 **행을 클릭**하면 이 데이터를 정리한 상세 팝업이 열립니다.

업체 명단이 바뀌면 새 엑셀을 같은 형식으로 정리한 뒤 `lib/suppliers.ts`의 `suppliers` 배열만
교체하면 됩니다. `/news`의 크롤링 대상 업체(우선순위 18개)도 이 배열에서 자동으로 뽑습니다.

## 전자공시시스템(DART) 연동

환경변수 `DART_API_KEY`(무료 발급: <https://opendart.fss.or.kr/>)가 설정되면:

- `/suppliers` 표에 **공시정보** 열이 채워집니다. 매일 08:00(KST)에 최근 7일 전체 공시 목록을
  조회해 99개 업체명과 매칭하고, 어제~오늘 신규 공시가 있으면 **"신규 N건"** 배지로 표시합니다.
- 업체 상세 팝업의 "전자공시(DART)" 섹션에 공시 목록과 개별 문서 링크(새 창)가 나옵니다.
- 구현: `lib/live/dart.ts`. 미설정 시 "미설정"으로 표시되고 나머지 기능은 정상입니다.
- 한계: 비상장·비외감 업체는 DART 공시 의무가 없어 매칭이 안 될 수 있고, DART 등록 회사명이
  다르면(법인격 표기 차이 등) 누락될 수 있습니다.

### 매일 08:00(KST) 자동 갱신

각 실시간 데이터는 하루(86400초) Next.js 캐시를 갖고 있고, `vercel.json`에 등록된 **Vercel Cron**이
매일 UTC 23:00(=KST 08:00)에 `/api/cron/refresh`를 호출해 캐시 태그(`supplier-news`,
`commodity-news`, `competitor-news`, `fx-rates`, `metal-prices`, `semiconductor-prices`,
`logistics`, `dart-disclosures`, `weather`)를 강제로 무효화합니다. 다음 접속 시 새 데이터로
다시 만들어집니다.

각 페이지 상단의 **"마지막 갱신 시각(KST)"** 이 이 캐시 스냅샷이 만들어진 시각입니다.
환율의 "ECB 기준일" 은 유럽중앙은행 고시일이라 주말·공휴일·이른 아침에는 전 영업일로 보이는
것이 정상이며(하루 1회, 대략 CET 16:00 고시), 실제 데이터 조회 여부는 "마지막 갱신 시각" 으로
판단하세요.

**주의**: Vercel Hobby(무료) 플랜은 크론이 정시가 아니라 해당 UTC 1시간 내 임의 시각에 실행됩니다
(즉 08:00~08:59 KST 사이 어느 시점). 더 촘촘한 스케줄이나 정시 실행이 필요하면 Pro 플랜이 필요합니다.
`CRON_SECRET` 환경변수는 Vercel이 프로젝트 배포 시 자동으로 만들어주므로 따로 설정할 필요는 없습니다.

## 아직 목업인 부분

`lib/data.ts`의 `fetchLogisticsStatus`는 아직 목업 스냅샷(대한민국 기준 중국·대만·미국·유럽·국내
구간, 리드타임은 모두 대한민국 문전 기준)을 반환합니다. 실제 연동 시 이 함수 내부만 교체하면 됩니다:

- 물류/리드타임: 선사·포워더 스케줄 API, Freightos/Drewry 운임지수, 미국·유럽 항만 대기
  데이터, 관세청 수출입 통관 정보

API 키가 필요한 경우 Vercel 프로젝트의 Settings > Environment Variables에 등록하고,
`process.env.YOUR_KEY` 형태로 불러오세요.

## 로그인 (아이디/비밀번호)

모든 페이지는 로그인 후에만 접근할 수 있습니다. 미인증 상태로 접근하면 `/login` 으로
이동합니다.

- 기본 계정: **아이디 `procurement` / 비밀번호 `rnaoxla2026!`**
- 계정·비밀키는 환경변수로 덮어쓸 수 있습니다 (`.env.example` 참고):
  - `AUTH_USERNAME`, `AUTH_PASSWORD`
  - `AUTH_SECRET` — 세션 쿠키 서명용 비밀키. **Vercel 배포 시 Settings > Environment
    Variables 에 임의의 긴 문자열로 반드시 설정하세요** (`openssl rand -hex 32`).
    미설정 시 개발용 기본값이 쓰여 세션 위조에 취약합니다.

로그인하면 12시간짜리 httpOnly 세션 쿠키(`scm_session`)가 발급되고, 우측 상단
"로그아웃" 버튼으로 해제할 수 있습니다. 인증 처리는 `middleware.ts` + `lib/auth.ts` +
`app/api/auth/*` 에 있습니다. 크론 엔드포인트(`/api/cron/refresh`)는 기존 `CRON_SECRET`
방식을 그대로 유지합니다.

## Vercel 배포

1. 이 폴더를 GitHub 저장소에 push (실제 재무 데이터가 포함되어 있으니 **Private 저장소** 권장)
2. vercel.com에서 GitHub 계정으로 로그인
3. "Add New... > Project"에서 해당 저장소 선택 (Next.js는 자동 감지됨)
4. **Settings > Environment Variables** 에 `AUTH_SECRET` (임의의 긴 문자열) 등록.
   계정을 바꾸려면 `AUTH_USERNAME` / `AUTH_PASSWORD` 도 함께 등록
5. Deploy — `vercel.json`의 크론이 자동으로 등록됩니다
6. 배포 완료 시 `https://프로젝트이름.vercel.app` 주소 생성
